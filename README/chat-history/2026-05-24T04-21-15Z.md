## Session 2 — Profile Page: Department → Role + Permission Overhaul

Remove the `department` input from the profile page, replace it with a `role` select, and change user permission levels to `owner`, `manager`, `senior`.

### Key Decisions

## Current Architecture

### Tech Stack
- **Frontend:** Next.js 16.2.6 (App Router, static export), Tailwind CSS v4, TypeScript strict, Jest + React Testing Library
- **Backend:** Fastify, Prisma ORM (MariaDB), JWT auth, Zod validation, Jest
- **Styling:** Zinc-800 dark palette, `#86efac` green accent, glassmorphism, gradient cards, custom scrollbar

### User Roles
| Role | Permissions |
|------|-------------|
| `owner` | Full access — edit profile, manage users, all features |
| `manager` | Standard access — cannot edit profile or manage users |
| `senior` | Standard access — cannot edit profile or manage users |

### Routes
| Path | Purpose |
|------|---------|
| `/` | Landing page |
| `/login`, `/register`, `/forgot-password`, `/reset-password` | Auth |
| `/dashboard` | Dashboard with stat cards + search |
| `/incidents` | Incident list with table |
| `/incidents/new` | Create incident form |
| `/profile` | User profile (view + password change, role edit for owners) |
| `/admin/users` | Owner-only: create/edit users |
| `/reports` | Reports |

### Data Flow
- Auth: `useAuth` context → `AuthProvider` fetches user via `GET /auth/me` on mount
- Dashboard stats: `GET /reports/summary`
- Incidents: `GET /incidents` with pagination/search/date filters
- Profile: read via `useAuth`, update via `PATCH /auth/users/:id` (owner own profile) or admin users page
- All authenticated requests include JWT from `localStorage`
